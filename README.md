# Relay

> Java/Spring으로 채팅 서버를 만들면서 **문제 발견 → 재현 → 해결책 비교 → 구현 → 테스트·측정 → 기록** 과정을 반복하는 학습 프로젝트

## 프로젝트 설명

Relay는 여러 사용자가 채팅방에서 실시간으로 메시지를 주고받는 서버입니다. 최소 기능에서 시작해 단계(Phase)별로 확장합니다.

채팅을 주제로 고른 이유는, 메시지 하나가 **연결 → 전달 → 저장 → 조회**되는 과정에서 순서, 중복, 유실, 지연 문제를 직접 관찰할 수 있기 때문입니다. 실시간 연결, 데이터 정합성, 동시성, 비동기 전달, 장애 복구, 성능 분석을 CRUD보다 깊게 다룰 수 있습니다.

이 프로젝트의 목표는 기술 목록을 채우는 것이 아닙니다. 다음 질문에 **근거와 실험 결과로 답할 수 있게 되는 것**이 목표입니다.

- 어떤 문제가 있었고, 왜 발생했는가?
- 어떤 해결책을 비교했고, 왜 그 방식을 선택했는가?
- 어떤 테스트로 검증했으며, 실제로 개선되었는가?
- 어떤 한계가 남았고, 더 큰 규모라면 어떻게 발전시킬 것인가?

## 진행 방식

- **문제 먼저**: 실패하는 테스트로 문제를 재현한 뒤 해결합니다.
- **단순한 해결 우선**: 새 기술은 재현된 문제가 있고, 더 단순한 대안을 검토한 뒤에만 도입합니다.
- **측정으로 판단**: 성능 개선은 같은 조건에서 측정한 전후 수치로만 주장합니다.
- **결정 기록**: 대안을 비교한 기술 선택은 ADR(Architecture Decision Record)로 남깁니다.

## 현재 상태

_2026-10-24 기준_

| Phase | 상태 | 내용 |
|---|---|---|
| P0 프로젝트 기반 구성 | 완료 | Java 21 toolchain, Spring Boot 4.1.2, Gradle Wrapper 9.8.2, Actuator health 확인 |
| P1 최소 실시간 채팅 서버 | **진행 중** | WebSocket 연결·종료, 방 관리, 브로드캐스트·격리, 비정상 입력·종료 처리, 기준 성능 측정 |

현재 동작하는 기능은 P0 범위(애플리케이션 기동, health 엔드포인트)까지입니다.

### 최근 결정: Raw WebSocket으로 시작

P1의 메시징 방식으로 STOMP 대신 Spring의 `WebSocketHandler`(Raw WebSocket)를 선택했습니다.

- STOMP를 쓰면 메시지 형식, 방 → 세션 매핑, 브로드캐스트, 끊긴 세션 정리를 프레임워크가 처리해 줍니다. 대신 그 안에서 생기는 문제가 가려집니다.
- 이 프로젝트는 문제를 직접 재현하는 것이 목적이므로, 이 부분을 직접 구현합니다.
- **재검토 조건**: 서버가 여러 대가 되어 서버 간 메시지 전달 문제가 재현되면, Raw 구조를 유지할지(Redis Pub/Sub, Kafka 등) STOMP + 외부 Broker로 바꿀지 다시 검토합니다.

## 로드맵

아래 기술은 **학습 후보**이며, 구현된 기능이 아닙니다. 각 Phase에서 문제가 재현될 때 도입 여부를 결정합니다.

| Phase | 핵심 질문 |
|---|---|
| P1 WebSocket | 연결·방·브로드캐스트·격리가 정확한가? 기준 성능은? |
| P2 영속화 (MySQL) | 메시지가 유실되지 않는가? 조회가 인덱스를 타는가? |
| P3 동시성 | 중복 저장이 없는가? 방 안의 순서는 무엇이 결정하는가? |
| P4 비동기 (Kafka) | 커밋과 발행 사이에 실패하면 무슨 일이 생기는가? |
| P5 Redis | 캐시가 실제로 빠른가? 정합성 비용은? |
| P6 다중 서버 | 다른 서버의 사용자에게 메시지가 전달되는가? |
| P7 신뢰성 | 구성 요소 장애 시 유실·중복 범위를 설명할 수 있는가? |
| P8 성능 | 병목은 어디이며, 개선을 수치로 보일 수 있는가? |
| P9 보안·운영 | 미인증 접근이 차단되는가? 배포가 자동화되었는가? |
| P10 회고 | 제거해도 되는 기술은 무엇인가? |

## 요구 환경

- JDK 21 (Gradle toolchain이 21을 찾아 사용합니다)
- 별도 Gradle 설치 불필요 (Gradle Wrapper 사용)
