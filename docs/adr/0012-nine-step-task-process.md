# ADR-0012. 과제 진행 체크리스트를 9단계로 교체

- 상태: Accepted
- 날짜: 2026-10-26
- 관련 Phase: P1-6 이후 전체
- 대체: [ADR-0003](0003-daily-progress-tracking.md)의 결정 ② "과제별 5단계 체크리스트" (P1-6부터)

## 배경

[CHG-003](../changes/003-ai-delegation-master-prompt.md)으로 마스터 프롬프트를 "AI 구현 위임 기반 사고력 훈련"으로 바꿨다. 학습자는 문제 정의·흐름 분석·질문 생성·설계·결과 해석을 맡고, 구현은 AI에 위임한다.

P1-1~P1-5를 돌아보면 세 가지가 부족했다.

- 시스템 흐름을 AI가 대부분 설명해서, 학습자가 흐름을 직접 구성한 비중이 낮았다 (P1-5: "계층을 나눠서 봐야 한다").
- 질문을 AI가 먼저 던졌다. 학습자가 스스로 확인 질문을 만드는 훈련이 따로 없었다.
- 5단계에서 "2. 고민"에 질문·힌트·위험·대안 비교가 모두 묶여 있어, 어떤 사고를 했는지 체크리스트로 구분되지 않았다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 5단계 유지, 9단계를 세부 절차로 포함 | ADR-0003·기존 기록·hook 변경 최소 | 흐름 분석·질문 생성이 "1. 정의" 안에 묻혀 건너뛰기 쉬움 |
| **B. 9단계 체크리스트로 교체 (P1-6부터)** | 흐름 분석·질문 생성·결과 해석·장애 실험이 각각 체크 항목으로 드러남 | 체크리스트가 길어짐, P1-5 이전과 형식이 다름 |

## 결정

B를 채택한다. 마스터 프롬프트 4절의 9단계를 그대로 체크리스트로 쓴다.

```markdown
### P1-X <과제명>
- [ ] 1. 문제 정의: 기술 이름 없이 문제·목적·기대 결과·성공 기준·모르는 것을 내가 작성
- [ ] 2. 흐름 분석: 내가 흐름 작성 → 코드와 비교해 교정 → 내 말로 다시 작성
- [ ] 3. 질문 생성: 사실·미확인 구분, 내가 확인 질문 작성(목적·확인 방법·결과별 다음 행동), 우선순위
- [ ] 4. 요구사항·위험: 요구사항·불변식·제약·비범위, 실패 시나리오(수량·시간·순서·실패·경계값, 문제 찾기 질문 6개)
- [ ] 5. 설계 결정: 대안 비교, 선택 기준, 성공 기준, 재검토 조건 → (필요 시) ADR
- [ ] 6. AI 구현·테스트: 구현 지시(범위·불변식·변경 금지 영역·검증 기준·보고 형식) → 구현·테스트 결과 보고
- [ ] 7. 결과 해석·코드 검토: 성공 기준 충족 여부, 확인한 것·못한 것, 핵심 코드 설명
- [ ] 8. 장애·운영 실험: 내가 세운 가설 → 실험 → 유지·수정·기각
- [ ] 9. 회고: 완료 기준 질문 10개 점검, 회고 기록
```

### 체크 규칙

- 1~5단계와 7~9단계는 학습자가 자신의 답을 적은 뒤에만 체크한다. Claude는 답을 먼저 나열하지 않고 질문을 하나씩 던진다.
- 2단계에서 학습자가 모르는 구성요소가 있으면 이해 모드로 설명한 뒤, 학습자가 흐름을 다시 작성해야 체크한다.
- 6단계는 구현과 테스트를 실제로 실행하고 결과를 보고한 뒤에 체크한다.
- [문제 찾기 질문 6개](../learning/problem-finding-questions.md)는 4단계(요구사항·위험)의 도구로 옮긴다.
- 작은 과제는 각 단계를 몇 문장으로 끝낸다. 8단계는 과제 성격상 실험할 장애가 없으면 이유를 적고 넘어갈 수 있다.

### 적용 범위

- P1-6부터 적용한다. P1-1~P1-5의 5단계 체크리스트와 기록은 그대로 둔다.
- ADR-0003의 나머지 결정(① `progress.md`, ③ journal, 세션 흐름, SessionStart hook)은 유지한다.

## 결과와 트레이드오프

- 체크리스트가 길어져 과제당 기록 비용이 늘어난다. 작은 과제는 단계별 한두 문장으로 줄인다.
- 단계가 잘게 나뉘어, 이미 이해한 부분까지 질문이 반복될 수 있다. 마스터 프롬프트 5절의 모드 전환 기준으로 줄인다.

## 재검토 조건

- 9단계 중 일부가 과제마다 반복적으로 형식적으로만 채워질 때
- 체크리스트 때문에 과제 하나가 지나치게 길어질 때
