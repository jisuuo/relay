# 문제 찾기 질문: 품질속성을 스스로 정의하는 방법

- 날짜: 2026-10-24
- 관련: [ADR-0003](../adr/0003-daily-progress-tracking.md) 5단계 중 "1. 정의", [Phase 1 plan](../phases/phase-01-websocket/plan.md) P1-3
- 계기: P1-3 정의 중에 던진 질문. "저런 품질속성을 알 수 있는 방법은? 내가 이런 문제가 있을 거라고 정의해 보고 싶은데"

## 핵심 질문

설계에 필요한 품질속성(정합성, 동시성 안전성 등)은 목록을 외워서 찾는 게 아니다. **정해진 질문을 시스템에 던지면** 나온다.
그렇다면 어떤 질문을 던지면 될까?

## 질문 6개

| # | 던질 질문 | 찾게 되는 품질속성 |
|---|---|---|
| 1 | **항상 참이어야 하는 문장은?** (불변식) | 정합성 |
| 2 | **누가 동시에 건드리나?** | 동시성 안전성 |
| 3 | **넣는 곳마다 빼는 곳이 짝지어 있나?** 특히 비정상 경로에서 | 자원 정리 (누수 없음) |
| 4 | **무엇이 커지면 비용이 같이 커지나?** | 효율 |
| 5 | **그게 지켜지는지 어떻게 확인하지?** | 테스트 가능성 |
| 6 | **서버가 죽으면? 두 대가 되면?** | 영속성·확장성 (범위 판단) |

### 질문을 쓰는 요령

- **1번이 출발점이다.** 불변식을 문장으로 적어 두면 2~4번이 따라 나온다.
  - "이 문장이 깨지는 순간은?"을 물으면 2번(동시성)으로 이어진다.
  - "이 문장이 영원히 참으로 남아 버리면?"을 물으면 3번(누수)으로 이어진다.
- **3번은 비정상 경로를 먼저 본다.** 정상 경로(`LEAVE`)는 누구나 떠올린다. 문제는 거의 항상 예외 경로(연결 끊김, 예외 발생, 타임아웃)에서 나온다.
- **6번은 "안 한다"고 결정하기 위한 질문이다.** 범위를 정하는 것도 설계다. 재현된 문제 없이 기술을 도입하지 않는다는 원칙(`docs/roadmap.md`)과 이어진다.

## 문제 문장으로 바꾸는 틀

질문으로 찾은 것을 아래 틀에 넣으면 그대로 테스트 시나리오가 된다.

> **[사건]**이 **[조건]**에서 일어나면 **[불변식/자원]**이 깨진다 → 결과: **[관찰 가능한 증상]**

예 (P1-1): 동시 등록이 `HashSet`에서 일어나면 세션 집합이 깨진다 → 결과: 10,000개 중 6,611~8,546개만 남는다.

## 적용 예: P1-3 채팅방 및 세션 관리

| # | 적용 |
|---|---|
| 1 | "S가 방 A의 세션 목록에 있다 ⇔ A가 S의 방 목록에 있다" |
| 2 | 여러 스레드가 같은 매핑에 `JOIN`·`LEAVE`·끊김을 동시에 처리한다 |
| 3 | `JOIN`이 넣은 것을 `LEAVE`와 연결 끊김이 모두 빼는가 |
| 4 | 방 → {세션들}만 있으면 끊김 정리 비용이 전체 방 수에 비례한다 |
| 5 | WebSocket 핸들러 없이 방 관리만 따로 테스트할 수 있는가 |
| 6 | 서버 재시작·다중 서버는 P1 범위 밖이다 |
